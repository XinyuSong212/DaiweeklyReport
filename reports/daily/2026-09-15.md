# Daily — 2026-09-15

## Decided

- **The report's job is surfacing reasoning, not collecting material.** Started
  from the usual premise — that the hard part is remembering by Friday what
  happened on Monday — and moved off it. Scoped to individual upward reporting
  with the explicit requirement that the report show the author's own thinking.
  Passed over a team-leader aggregation mode: that is a dedup-and-rollup
  problem, not a reasoning-capture one.

- **Conversation transcripts are a first-class source; calendar and chat are
  out.** Both need credentials or degenerate into manual paste. Confirmed
  transcripts are cleanly parseable — human turns isolate on
  `origin.kind == "human"` with no `toolUseResult`, and `AskUserQuestion`
  stores the chosen answer *and* the options passed over, which is a recorded
  tradeoff with the roads-not-taken still attached.

- **Daily is an ingest; weekly consumes a journal, not transcripts.** Rejected
  the conventional reading of weekly as "summarize seven dailies" — dailies are
  event-shaped and the rejected-alternative detail is already gone by then — and
  also rejected re-parsing a week of raw transcripts, which neither fits in
  context nor survives session rollover. Daily now writes a durable
  `journal/YYYY-MM.jsonl`; the daily report is a byproduct of that write.

- **Collectors optimize for recall, the model supplies precision.** A missed
  pushback is unrecoverable once a transcript ages out; a false positive costs
  one line of reading. The classifiers over-trigger on purpose, and both the
  script docstring and SKILL.md say so, so nobody later "fixes" it.

- **The git collector, assumed trivial, held two silent data-loss bugs.**
  `git log --since=2026-09-15` excluded a commit made at 00:24:32 while the
  clock read 00:24:48 — git's approxidate fills a missing time-of-day with the
  *current* time, not midnight, so a morning daily run drops everything
  committed earlier that day. Separately, `--numstat` prints its stat block
  after the formatted header, so a trailing record separator sliced each
  commit's file stats onto the front of the next record. Both returned clean
  zeros instead of failing. Rejected shipping on "it runs without error":
  running without error was exactly what both defects looked like.

## Moved

- Wrote the skill: `SKILL.md`, two references (journal schema and mining rules,
  report anatomy), two collectors.
- Both collectors verified against real data. Tradeoff extraction recovers all
  three questions asked today with their passed-over options; git collection
  went from 0 commits / 0 files to 1 commit / 11 files / +1132 after the fixes.
