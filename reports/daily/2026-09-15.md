# Daily — 2026-09-15

Built a daily/weekly report skill end to end, then ran it against its own build
day and found it had been under-reporting.

## Decided

- **A status report's job is surfacing reasoning, not collecting material.**
  Started from the usual premise — that the hard part is remembering by Friday
  what happened on Monday — and moved off it. Passed over a team-leader
  aggregation mode: that is a dedup-and-rollup problem, not a reasoning-capture
  one. This reframed everything downstream: the tool is a decision capturer
  whose output format happens to be a report.

- **Conversation transcripts are the primary source; calendar and chat are
  out.** Git records the path taken; only the transcript records the paths
  rejected. Dropped calendar and chat integration — both need credentials or
  degenerate into manual paste.

- **Daily is an ingest; weekly consumes a journal, not transcripts.** Rejected
  the conventional reading of weekly as "summarize seven dailies" — dailies are
  event-shaped and the rejected-alternative detail is gone by then — and also
  rejected re-parsing a week of raw transcripts, which neither fits in context
  nor survives the retention window. Daily now writes a durable
  `journal/YYYY-MM.jsonl`; the daily report is a byproduct of that write.

- **Verified the source's guarantees instead of assuming them.** Parsing one
  live session proved the format, not the guarantee the whole design rests on.
  Checking the docs turned up four limits, now documented: 30-day default
  retention, local CLI sessions only, set-aside `.orphaned-` copies that
  double-count, and plaintext storage that captures whatever a tool printed.
  The retention ceiling is the load-bearing one — it turns "daily should run"
  into "daily must run".

- **The collectors, assumed to be the simple half, held four silent defects.**
  Two in git collection, found by inspection: `git log --since=2026-09-15`
  excluded a commit made at 00:24:32 while the clock read 00:24:48, because
  git's approxidate fills a missing time-of-day with the *current* time rather
  than midnight — a morning run drops everything committed earlier that day.
  And `--numstat` prints its stat block after the formatted header, so a
  trailing record separator sliced each commit's file stats onto the front of
  the next record. Two more in conversation collection, found by running the
  tool on today (below). All four returned clean zeros instead of failing.
  Rejected shipping on "it runs without error": running without error was
  precisely what every one of them looked like.

- **The first real run under-reported, and the zero was the tell.** Today's
  collection returned 11 prompts, 0 pushbacks, 0 endorsements — for a day with
  five commits, a corrected assumption and a reversed design. Six of the 11
  "prompts" were harness injections (skill bodies, image placeholders), which
  carry `isMeta` and are now excluded. More importantly the classifier had no
  pattern for **skepticism** at all, so the day's most consequential pushback —
  a challenge to whether transcripts really are recorded locally, which is what
  produced the four limits above — scored as an ordinary prompt. Skepticism is
  pushback: it disputes a claim the work rests on. Same window now reads 6
  prompts, 1 pushback, 1 endorsement.

## Moved

- Skill shipped: `SKILL.md`, two references (journal schema with mining rules,
  report anatomy with templates), two standalone collectors.
- Design doc published covering the architecture, the four-tier signal
  hierarchy, and one real decision traced through all four stages.
- Journal holds 8 entries, two of which `supersede` earlier ones — the source
  assumption and the collector's recall claim were both corrected within the
  same day.

## Open

- **Nothing enforces that the daily run happens**, and weekly accuracy depends
  on it. A cron or `SessionStart` hook is the obvious fix; not built. This is
  the largest remaining gap.
- Classifier patterns are hand-written for Chinese and English. Today added
  skepticism; the category was missing entirely, so others may be too. Real
  usage is the only way to find them.
- Web-session conversations cannot be mined at all. If much of the work happens
  there, coverage is worse than the journal makes it look.

## Note on evidence quality

Five of today's eight entries rest on the author's own words or recorded
choices. Two — the daily/weekly split and the single-invocation setup — were
assistant-proposed and proceeded with rather than explicitly chosen; both
entries record that rather than inflating it.
